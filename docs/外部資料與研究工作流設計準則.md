# 外部資料 / 研究類工作流 — 設計準則(資料真實性)

> 適用範圍:任何會「抓外部資料(爬蟲 / web_search)」或「用 LLM 產報告 / 分析 / 比較」的節點或功能。
> 目的:**好看的報告 ≠ 真實**。讓系統「沒料就停 / 老實說」而不是腦補,並讓開工前就照清單做、不再事後踩坑。
> 由來:2026-06 Hero 卡2~8 實測 + 讀產出發現「報告掩蓋爬蟲失敗、subagent 編造有來源的假數據」後收斂。

---

## 核心心智模型:資訊漏斗

```
抓取(資料量最大) → 蒸餾 / 分析(收斂) → 報告(最精要)
     ↑ 真實性的源頭                          後段只能「蒸餾既有」、不能「無中生有」
```

失真幾乎都發生在:**抓回的料太少,但下游為了把報告寫滿,自己補(腦補數據 / 杜撰來源)**。
所以防線要同時管「上游有沒有抓到真料」與「下游能不能只用既有料」。

---

## 五條鐵律(+ V5 落地機制)

| # | 原則 | V5 怎麼落地(機制) |
|---|------|------------------|
| 1 | **接地 Grounding**:報告只能用「實際抓回 / 上游實際提供」的資料,引用要對得回真實來源 | `subagent_runner._inject_research_integrity` 注入兩條 loop(text/native)的 system prompt |
| 2 | **不確定就 abstain**:沒料就老實標「資料不足 / 無法佐證」,**不腦補、不杜撰來源連結** | 同上;誠信鐵律第 1~4 點 |
| 3 | **retrieve-more 而非編造**:料不夠時,先用上一步的線索 / 關鍵字當起點,自己 `web_search` 再搜補足 | researcher / report_writer / summarizer / trend_analyst / data_analyst / comparator 都掛 `web_search`(`subagent_roles.yaml`) |
| 4 | **充足度閘(硬守門)**:抓取 / 收料步驟填 `output.expect` 描述「怎樣算收集到足量真實資料」→ AI 內容驗證、抓太少 / 全空 / 404 就 `failed`、不讓下游無料硬寫 | `runner.py` web_crawler 分支:有 expect→`validate_step` 讀內容驗;無 expect→`_crawl_looks_failed` 掃 status_code/子頁。**別用死字數門檻**(主題冷熱差很多),用 expect 文字讓 AI 判 |
| 5 | **完成守門(硬守門)**:步驟宣告了 `output.path` 卻沒產出任何檔 → `failed`(擋假完成);內容是 404/空頁/錯頁也算失敗 | `runner.py` 通用閘(`_missing_promised_output`)+ web_crawler 內容驗證 |

## 規劃 / 撰寫工作流時的 pre-flight 清單

開工前(AI 助手規劃時 / 人工拉節點時)逐項確認:

- [ ] **每個爬蟲 / 收料步驟都填 `output.expect`**,描述「怎樣才算抓到真實目標資料(非 404 / 空 / 離題)」
- [ ] **沒給確切 URL → 反問使用者**,絕不可編 `example.com` 之類佔位假網址硬跑
- [ ] 報告 / 分析步驟的 batch **明寫「只根據上一步抓回的資料寫、資料不足就說資料不足」**
- [ ] 分析 / 撰寫 role 有掛 `web_search`(缺料能自己補,而非腦補)
- [ ] 產檔步驟有宣告 `output.path`(完成守門才接得住)
- [ ] 多來源(競品 / benchmark):每來源各自驗,別把 N 站塞一個爬蟲節點
- [ ] 產 Word → 用 `python-docx`(不掛 docx-js,gemma 寫不動嚴格 API);內容多先出 md 再轉檔

## 三個誠實的天花板(別過度承諾)

1. **鐵律 1~3 是 prompt 軟約束**:免費模型(gemma)仍可能微幅潤飾。**硬保證的是 4、5(驗證閘)**。
2. **沒有逐句 faithfulness 自動核對**(每個數字追回原文)——那是更高標但很重;目前靠「先抓真料 + 限定既有資料」逼近。
3. **模型能力是變數**:深度研究 / 長報告 / 嚴格格式產出,gemma 較弱、Claude 較穩;重任務理想切強模型(能力天花板路由)。

## 良好行為長相(2026-06 實測「2026 AI 伺服器市場」深度研究)

- researcher 多面向 `web_search` 4 次(市場規模 / 競爭格局 / 技術趨勢 / 需求驅動),各回 ~21KB 真實資料
- **對矛盾數據老實並陳**:「Research Nester 2,236 億 vs Roots Analysis 470 億(註:定義範圍不同)」、CAGR 給區間 18%~35.2% 並列三來源,**不假裝單一精確值**
- 附真實來源 URL、真實產品名(Dell PowerEdge XE9712 / NVIDIA GB200 / ZT Systems ACX200)

對照反例(修正前):benchmark 研究編一張假 Elo 表 + 假來源連結 → 看似專業實則造假。
